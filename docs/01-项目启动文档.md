## 1. 项目概述

### 1.1 项目简介
NL2TK 是一个基于 AI 的自动化短视频生成平台，通过热点追踪、智能剧本生成和视频制作流程，实现从热点发现到视频发布的全自动化工作流。

### 1.2 核心价值
- **热点捕捉**: 实时追踪多平台热点，把握流量风口
- **智能创作**: AI 驱动的剧本生成，提升内容质量
- **自动化生产**: 端到端自动化流程，降低人工成本
- **规模化运营**: 支持批量生产，满足矩阵号运营需求

### 1.3 业务目标
- 缩短视频生产周期至 30 分钟以内
- 支持单日产出 10+ 条高质量短视频
- 热点响应速度 < 2 小时
- 视频质量达到商业发布标准

## 2. 系统架构

### 2.1 架构设计原则
- **微服务化**: 模块独立部署，便于扩展和维护
- **松耦合**: 服务间通过标准接口通信
- **可配置**: 支持策略配置，无需修改代码
- **高可用**: 关键服务多实例部署
- **可观测**: 完善的监控和日志体系

### 2.2 核心模块

#### 2.2.1 提示词优化模块 (Prompt Optimizer)
**职责**: 优化用户输入的提示词，提升 AI 生成质量
- 提示词模板管理
- 上下文增强
- 关键词提取与扩展
- A/B 测试支持

#### 2.2.2 热点追踪模块 (Trending Tracker)
**职责**: 多源热点数据采集与分析
- 多数据源支持（详见 3.1）
- 热点评分与排序
- 趋势预测
- 去重与聚合

#### 2.2.3 文生剧本模块 (Script Generator)
**职责**: 基于热点和提示词生成视频剧本
- 多 LLM 模型支持（阿里通义、腾讯混元等）
- 剧本结构化输出（镜头、文案、时长）
- 剧本质量评估
- 人工审核接口

#### 2.2.4 剧本生视频模块 (Video Generator)
**职责**: 将剧本转换为成品视频
- 视频生成策略（Sora、Gemini、阿里云 API）
- 素材管理（音频、图片、字幕）
- 视频后期处理（剪辑、特效、配音）
- 多分辨率输出

#### 2.2.5 任务调度模块 (Scheduler) ⭐ 新增
**职责**: 管理整个工作流的执行
- 定时任务配置
- 工作流编排（DAG）
- 失败重试机制
- 并发控制

#### 2.2.6 内容管理模块 (Content Manager) ⭐ 新增
**职责**: 管理生成的内容资产
- 剧本版本管理
- 视频素材库
- 内容审核记录
- 发布历史追踪

## 3. 详细需求规格

### 3.1 热点追踪模块详细需求

#### 3.1.1 数据源策略
| 数据源类型 | 技术方案 | 数据质量 | 实现优先级 |
|----------|---------|---------|----------|
| 抖音热榜 | Python + requests/Scrapy | 中 | P0 |
| TikTok 热榜 | 第三方 API（蝉妈妈/新抖） | 高 | P0 |
| 通用热点 | RSS 聚合 + 百度指数 API | 中 | P1 |
| 微博热搜 | API + 爬虫混合 | 高 | P1 |
| 小红书热门 | 爬虫 | 中 | P2 |

#### 3.1.2 策略配置设计
```yaml
# 配置示例
trending_sources:
  - name: douyin_hot
    type: scraper
    enabled: true
    schedule: "*/30 * * * *"  # 每30分钟
    priority: high
    
  - name: chanmama_api
    type: api
    enabled: true
    api_key: ${CHANMAMA_API_KEY}
    rate_limit: 100/hour
```

#### 3.1.3 功能需求
- ✅ 支持多数据源并行采集
- ✅ 数据去重与标准化
- ✅ 热度评分算法（时间衰减 + 多维度评分）
- ✅ 热点分类（娱乐、科技、社会等）
- ✅ 反爬虫机制（代理池、请求头轮换、频率控制）
- ✅ 异常处理与降级策略

### 3.2 文生剧本模块详细需求

#### 3.2.1 LLM 模型策略
| 模型提供商 | 模型名称 | 适用场景 | 成本 | 优先级 |
|----------|---------|---------|-----|--------|
| 阿里云 | 通义千问 | 通用剧本生成 | 低 | P0 |
| 腾讯云 | 混元 | 长文本生成 | 中 | P1 |
| 智谱 AI | GLM-4 | 创意内容 | 中 | P1 |
| 百度 | 文心一言 | 垂直领域 | 低 | P2 |

### 3.3 剧本生视频模块详细需求

#### 3.3.1 视频生成策略
| 策略 | 技术方案 | 质量 | 速度 | 成本 | 优先级 |
|-----|---------|-----|-----|-----|--------|
| Sora | OpenAI API | 极高 | 慢 | 高 | P0 |
| Gemini | Google API | 高 | 中 | 中 | P0 |
| 阿里云 | 通义视频生成 | 中 | 快 | 低 | P1 |
| 本地部署 | Stable Video Diffusion | 中 | 中 | 极低 | P2 |

#### 3.3.2 视频后期处理
- 字幕生成与叠加（SRT 格式）
- 背景音乐混音
- 转场特效
- Logo/水印添加
- 多平台格式适配（抖音 9:16、横屏 16:9）

### 3.4 任务调度模块详细需求

#### 3.4.1 调度功能
- ✅ Cron 表达式定时任务
- ✅ 工作流 DAG 定义（热点采集 → 剧本生成 → 视频制作）
- ✅ 任务优先级队列
- ✅ 失败重试（指数退避）
- ✅ 任务超时控制
- ✅ 并发数量限制

#### 3.4.2 工作流示例
```yaml
workflow:
  name: auto_video_generation
  schedule: "0 */2 * * *"  # 每2小时执行
  steps:
    - id: fetch_trending
      module: trending_tracker
      timeout: 300
      retry: 3
      
    - id: generate_script
      module: script_generator
      depends_on: [fetch_trending]
      parallel: 3  # 并发生成3个剧本
      
    - id: create_video
      module: video_generator
      depends_on: [generate_script]
      timeout: 1800
```
